# 検索カードの作成と一度だけの修復

検索カードを作るとき、配備IDなどの長い識別子は本文にある役割の表現へ置き換える。本文に無い役割や別名は作らない。意味のある数値・否定・条件・版を残す。公開してよい識別子は本文に保持でき、本文の語彙検索やgetで確認する。秘密の実値は本文にも保存しない。

- 本文保存済み、card ok: 返されたIDと版を成功として保持し終了。
- 本文保存済み、card pending: 本文書込を繰り返さず、返されたIDと版にsearch_cardを呼ぶ。capture等では項目ごとの状態を見て、成功項目を再作成しない。
- 本文未保存、カード入力invalid_input: カードを直し、元の書込を同じidempotency_keyで再送。本文未保存か不明なら応答の状態を確認し、保存済みと推測しない。

pending修復は一度だけ。既存の固定reasonと元の本文からカードを作り直す。secret_like / uuid_like / hex_likeは拒否値を復元・出力せず役割を説明する。claim_not_in_bodyは本文に無い主張をカードから除くか訂正し、本文へ架空の説明を足して検査を通さない。接頭辞だけの許可や一括の自動削除は使わない。

通信結果が不明なら同じ入力と同じキーで再送する。内容を変更する場合は別の修復キーを使う。ただし本文未保存のinvalid_input修正は元の書込キーを維持する。二度目の拒否はpendingを残して停止し、本文の保存とカード未修復を区別して伝える。

version_conflictはgetで現在版・本文・所有を確認する。自分の記憶の同じ本文に対するカードかを確認し、古い本文のカードを現在版へ流用しない。forbidden / quota / infrastructureは自動修復を止めて未修復を伝える。管理者DBのsearch-card-reclaimは本人カード修復に使わない。
