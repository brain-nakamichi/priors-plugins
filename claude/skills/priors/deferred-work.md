# 延期した対応と認証情報の露出

採用された未完了の後回し・あとで・延期・利用者の手元作業は、その場で既存workを確認して残す。否定・引用・完了報告を区別し、会話の一覧や短期メモだけに置かない。延期は完了や取消ではない。保存成功のIDを確認し、失敗なら未保存と報告する。

秘密疑いと露出申告は有効性・侵害の証明ではない。入力本文・部分値・hashをshell引数、tool query、記憶、ログへ転記せず安全な要旨を使う。自動失効・発行はしない。値を含まない申告だけでは検索を抑止しない。フックは利用者入力だけが対象で、tool出力は対象外。クライアント会話ログに既にある実値は消せない。

サービス・用途・事象が同じworkを再利用する。最新や単語一致だけで選ばず、曖昧なら候補を提示する。既知IDはfull briefで読み、部分取得を不存在と扱わない。明示ID不明を新規作成へfallbackしない。他AI所有は編集せず自分の根拠を共有する。closedは同じ事象の再開か新露出か区別する。

新事象は本文に由来しないUUIDのidempotency_keyを明示する。結果不明なら同じキーと引数で再送し、work_eventの版競合は最新版を再確認する。同時作成の完全排他は保証しない。

完了は全確定対象の旧値失効と新値発行、または不要理由の確認、全利用先更新、必要な接続と非秘密の失効確認が条件。3状態を全対象で評価し、部分結果は根拠noteへ分ける。新接続だけで旧値失効を認定せず、申告と実測を分ける。再配備は必要性を確認した場合だけ。旧値の再提示・試用は禁止。

秘密疑い・検査不能ではhashと通常候補キューを省略する。監査へ固定カテゴリとランダムな印だけを残し、Stopが当該ターンの件数で作業確認を促す。これは保存不足の断定でも作業保存の代行でもない。I/O障害でも会話は続け、値や例外のmessageは出さない。
